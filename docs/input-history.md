# Input history

```php
use NeuronInteraction\InputHistory\InputHistory;

$inputs = new InputHistory($storage);
$conversation->setInputHistory($inputs);
$stream = $conversation->sendInput('A message exactly as submitted');
$submitted = $inputs->list(); // Oldest first, across all Sessions.
```

With `setInputHistory()`, Conversation records original submissions synchronously
in `sendInput()`, before processors and stream consumption. This includes Command
invocations and excludes prompts generated by Commands. String inputs retain their
exact syntax; a `CommandInput` is stored as its identifier followed by a space and
its nonempty value. Recording also occurs when processing or execution later fails.
For recording at enqueue time, clients can call `append()` directly instead. Messages without visible
content are ignored; only consecutive exact duplicates collapse. Each read and append uses the
current Storage sequence, so existing instances see one another's submissions.
Simultaneous writes are not coordinated by this module; Adapters must serialize
them when sharing Storage across concurrent writers.

InputHistory only persists submissions. The consumer owns the navigation position,
the current draft, and keyboard or button handling. Both terminal and web clients
can load `list()` and implement recall locally.

`append()` accepts a Neuron `UserMessage`, including plain text and Command
syntax. Its content blocks and metadata are persisted together, including
image-only and file-only inputs. `list()` returns `list<UserMessage>` in
chronological order.

All stored entries use Neuron's serialized user-message representation.
Invalid entries, including plain strings, are rejected. No previous-format
reader or migration is supplied. Consecutive duplicate comparison includes
content and metadata, excluding Neuron's automatically generated message ID.
