# HTTP response stop

`StoppableHttpClient` and `StoppableStream` implement the HTTP composition
pattern described in [the Neuron article](https://inspector.dev/how-to-stop-a-streamed-ai-response-mid-flight-in-neuron-ai-v3/).
The Host creates a `StopSignal` with its Storage and application-selected key.
It calls `clear()` before streaming and `request()` when the user requests a
stop. Namespace and document format are private to `StopSignal`. `StoppableStream::eof()` reads and consumes
that flag, closes its inner stream, and reports ordinary EOF. Neuron can then
finalize the partial Assistant message and save History and Agent steps itself.

## Configure the provider

```php
use NeuronAI\Agent\Agent;
use NeuronAI\Chat\Messages\Stream\Chunks\TextChunk;
use NeuronAI\Chat\Messages\UserMessage;
use NeuronAI\HttpClient\GuzzleHttpClient;
use NeuronAI\Providers\OpenAI\OpenAI;
use NeuronInteraction\Http\StoppableHttpClient;
use NeuronInteraction\Http\StopSignal;
use NeuronInteraction\Storage\FileStorage;

$storage = new FileStorage('/app/interaction-state');
$chatId = 'chat-42'; // Chosen and authorized by the Host.
$stopSignal = new StopSignal(storage: $storage, key: $chatId);
$agent = new Agent();
$agent->setAiProvider(new OpenAI(
    key: $apiKey,
    model: $model,
    httpClient: new StoppableHttpClient(
        inner: new GuzzleHttpClient(),
        stopSignal: $stopSignal,
    ),
));
```

Use `InMemoryStorage` for one process. `StopSignal` instances sharing in-memory state
must hold the same Storage instance. `FileStorage` works across processes
using the same filesystem; Hosts on multiple servers can supply another
shared implementation of `StorageInterface`.

## Stream normally

```php
$stopSignal->clear();

foreach ($agent->stream(new UserMessage($prompt))->events() as $event) {
    if ($event instanceof TextChunk) {
        echo $event->content; // Or send an SSE event to the frontend.
    }
}
```

The consumer continues through all events. There is no stop check or `break`
in this loop, and no library lifecycle to start or finish around it.

## Request a stop

The stop endpoint, or a keyboard handler in the same process, writes:

```php
$stopSignal->request();
```

For a separate endpoint, create a new `StopSignal` using Storage at the same
location and the same application-selected key:

```php
$stopSignal = new StopSignal(
    storage: new FileStorage('/app/interaction-state'),
    key: $chatId,
);
$stopSignal->request();
```

`isRequested()` reads the current signal; it does not consume it. Repeated
`request()` and `clear()` calls are idempotent. Constructing the signal writes
nothing.

The Host must authorize that key for the current user. The streaming
request and stop endpoint need separate server workers so they can run
concurrently. Keep the frontend's stream connection open while requesting stop.

The flag is written only on Stop. The stream deletes it when consumed, and
keeps its own closed state so subsequent EOF checks do not consume another
flag. A normal response creates no Storage document or directory. No IDs,
expiry or maintenance schedule are generated by the module. An unconsumed
flag remains until the Host clears it before the next stream; applications
retiring keys permanently own any additional cleanup.

## Keys and polling

Use a conversation key when the Host serializes Turns within that conversation.
Different concurrently active streams need different keys. Do not retain a live
old stream while reusing its key. A late stop for a reused conversation key can
stop the new response; Hosts requiring response-level isolation must choose a
fresh response key and communicate it to their frontend themselves.

`pollInterval` defaults to 0.01 seconds. The stream reads Storage at most once
per interval, even when the provider calls `eof()` per byte. Polling happens
only when the provider checks EOF; there is no background task.

An optional `onPoll: Closure(): void` runs before each Storage check. A TUI
Host supplies a callback calling `Amp\delay(0)` so buffered provider data still
allows terminal input to run. The module has no Amp or terminal dependency.

## Limits

This stops an HTTP response, not an entire tool-using Turn. Local tools continue;
follow-up inference can start, and consumes no stop unless another flag is
written. Partial tool calls retain the provider's own EOF semantics. Neuron
saves its own final message; no interruption metadata or History repair is added.

A stop cannot abort a blocked read or an HTTP request still waiting to return
its stream. Actual resource closure depends on the inner transport; remote
model generation and billing cancellation are not guaranteed. Natural EOF can
win over a pending flag. Storage failures propagate to the Host.
