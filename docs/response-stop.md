# HTTP response stop

Use Neuron AI 4's native `StoppableHttpClient` and `StoppableStream` to stop
HTTP streaming. Neuron Interaction supplies `StopSignal::stopCallback()`, a
`Closure(): bool` that connects Neuron to a shared Storage flag.

The Host creates a `StopSignal` with its Storage and application-selected key.
It calls `clear()` before streaming and `request()` when the user requests a
stop. The callback reads and consumes that flag; Neuron marks the stream as
intentionally stopped and closes its transport. Neuron can finalize a partial
Assistant message with the `stopped` finish reason and persist it. Stopping before
any text raises `ProviderException`.

## Configure the provider

```php
use NeuronAI\Agent\Agent;
use NeuronAI\Chat\Messages\Stream\Chunks\TextChunk;
use NeuronAI\Chat\Messages\UserMessage;
use NeuronAI\HttpClient\Curl\CurlHttpClient;
use NeuronAI\Providers\OpenAI\OpenAI;
use NeuronAI\HttpClient\StoppableHttpClient;
use NeuronInteraction\Interruption\StopSignal;
use NeuronInteraction\Storage\FileStorage;

$storage = new FileStorage('/app/interaction-state');
$chatId = 'chat-42'; // Chosen and authorized by the Host.
$stopSignal = new StopSignal(storage: $storage, key: $chatId);
$agent = Agent::make()->setThreadId($chatId);
$agent->setAiProvider(new OpenAI(
    key: $apiKey,
    model: $model,
    httpClient: new StoppableHttpClient(
        client: new CurlHttpClient(),
        shouldStop: $stopSignal->stopCallback(),
    ),
));
```

Use `InMemoryStorage` for one process. `StopSignal` instances sharing in-memory state
must hold the same Storage instance. `FileStorage` works across processes
using the same filesystem; Hosts on multiple servers can supply another
shared implementation of `StorageInterface`.

## Stream normally

```php
$stopSignal->clear();

foreach ($agent->stream(new UserMessage($prompt)) as $event) {
    if ($event instanceof TextChunk) {
        echo $event->content; // Or send an SSE event to the frontend.
    }
}
```

The consumer continues through all events. There is no stop check or `break`
in this loop, and no library lifecycle to start or finish around it.

## Request a stop

The stop endpoint, or a keyboard handler in the same process, writes:

```php
$stopSignal->request();
```

For a separate endpoint, create a new `StopSignal` using Storage at the same
location and the same application-selected key:

```php
$stopSignal = new StopSignal(
    storage: new FileStorage('/app/interaction-state'),
    key: $chatId,
);
$stopSignal->request();
```

`isRequested()` reads the current signal; it does not consume it. Repeated
`request()` and `clear()` calls are idempotent. Constructing the signal writes
nothing.

The Host must authorize that key for the current user. The streaming
request and stop endpoint need separate server workers so they can run
concurrently. Keep the frontend's stream connection open while requesting stop.

The flag is written only on Stop. The callback deletes it when consumed.
Neuron remembers that the stream was stopped and does not ask its callback again,
so subsequent EOF checks cannot consume another flag. A normal response creates
no Storage document or directory. No IDs,
expiry or maintenance schedule are generated by the module. An unconsumed
flag remains until the Host clears it before the next stream; applications
retiring keys permanently own any additional cleanup.

## Keys and polling

Use a conversation key when the Host serializes Turns within that conversation.
Different concurrently active streams need different keys. Do not retain a live
old stream while reusing its key. A late stop for a reused conversation key can
stop the new response; Hosts requiring response-level isolation must choose a
fresh response key and communicate it to their frontend themselves.

`stopCallback()` accepts an optional `pollInterval`, defaulting to 0.01 seconds.
Each returned callback reads Storage at most once per interval, even when the
provider calls `eof()` per byte. A native client retains its callback across
streams. Create separate clients and callbacks for concurrent response keys.
Polling happens only when Neuron invokes the callback; there is no background task.

An optional `onPoll: Closure(): void` runs before each Storage check. A TUI
Host supplies a callback calling `Amp\delay(0)` so buffered provider data still
allows terminal input to run. The module has no Amp or terminal dependency.

```php
$callback = $stopSignal->stopCallback(
    onPoll: static function (): void { \Amp\delay(0); },
    pollInterval: 0.01,
);
$client = new StoppableHttpClient(client: $httpClient, shouldStop: $callback);
```

Creating the callback performs no polling or Storage access. `isRequested()`
remains a read without consumption; invoking the callback consumes a requested
stop when its polling interval allows a check. The callback can be reused for
later responses; Neuron keeps the stopped state on each individual stream.

## Limits

This stops an HTTP response, not an entire tool-using Turn. Local tools continue;
follow-up inference can start, and consumes no stop unless another flag is
written. Neuron discards incomplete tool calls on an intentional stop. A stream that
ends without its provider's closing event and without an intentional stop is an
error. Neuron owns response metadata and message persistence.

A stop cannot abort a blocked read or an HTTP request still waiting to return
its stream. Actual resource closure depends on the inner transport; remote
model generation and billing cancellation are not guaranteed. Neuron checks the stop callback before natural EOF, so it can consume a stop even
when the transport has already reached EOF. The signal is consumed before Neuron
closes the transport; transport errors still propagate. Reads and explicit closes
follow the native transport's behavior. Storage failures propagate to the Host.

## Migrating the HTTP wrappers

Replace `NeuronInteraction\Http\StoppableHttpClient` with
`NeuronAI\HttpClient\StoppableHttpClient`. Pass `client:` instead of `inner:`,
and `shouldStop: $stopSignal->stopCallback()` instead of `stopSignal:`. Move
`onPoll:` and `pollInterval:` into `stopCallback()`. The custom
`NeuronInteraction\Http\StoppableStream` has been removed; Neuron owns HTTP
stream stopping.
